# 0.7.0 Local HIT 时间分布

- 日期：2026-11-25
- 环境：与 `0.6.1-baseline.md` 相同，SQLite + file cache + PHP built-in server，9 worker
- 场景：B2 Local HIT，商品页 `/page-cache-test-product/`
- 方法：`Maho\Profiler` 临时启用，20 个连续请求，记录每个请求的总耗时和 timer；取 median / p95
- 注意：profiler 只用于本次分析，`public/index.php` 已恢复，没有提交

## 1. 结果

| Timer | median | p95 | 次数 |
|---|---:|---:|---:|
| 请求总耗时 | 20.875 ms | 27.301 ms | 1 |
| `mage` | 18.332 ms | 21.625 ms | 1 |
| `mage::app::init::stores` | 7.697 ms | 11.591 ms | 1 |
| `mage::dispatch::routers_match` | 4.640 ms | 6.044 ms | 1 |
| `dispatch.controller.action.predispatch` | 4.173 ms | 5.447 ms | 1 |
| `cache.load` 全部 | 2.781 ms | 3.757 ms | 13 |
| `mage::app::init::config::load_cache` | 1.529 ms | 2.237 ms | 1 |
| `mage::app::init::system_config` | 0.744 ms | 1.411 ms | 1 |
| `mage::dispatch::db_url_rewrite` | 0.334 ms | 0.564 ms | 1 |
| `mage::app::init_front_controller` | 0.216 ms | 0.283 ms | 1 |
| `serveLocalHit` | 0.657 ms | 1.352 ms | 1 |

## 2. 结论

- 页面缓存自己的命中逻辑约 **0.66 ms**，占单请求约 **3%**。即使降到 0，也拿不到 P95 15% 的改善。
- 主要成本在 Maho 启动和路由：`mage` 18.3 ms，其中 stores 7.7 ms、routing 4.6 ms。
- `cache.load` 全请求 13 次，页面缓存只占 3 次；CacheEnvelope 省下的 2 次读取绝对值很小，和之前的 +2.56% / P95 -1.42% 相符。
- 继续减少页面缓存读取、压缩 entry 或调整 context 不能达成 G9。需要跳过 Maho bootstrap 的独立快速路径，或使用已经存在的 Static Export / 反向代理层。
- 不建议为了 P95 15% 取消 global/URL version 检查或降低 context 隔离；正确性优先。

## 3. 对 G9 的影响

G9 的 `Local HIT P95 改善 ≥15%` 在当前“PHP 参与每个命中”的架构下不可达。可选路线：

1. 把 0.7.0 的 G9 标记为未通过，按现状发布，把 15% 目标转到 Static Export 或 FR-19 多节点。
2. 另立 RFC，做 bootstrap 前的 fast path：轻量读取 URL、store、session bypass 和 envelope，直接输出响应。这会重复路由和 context 逻辑，安全和维护成本高，不应塞进 0.7.0。
3. 在生产 PHP-FPM + OPcache/JIT 环境复测，确认 bootstrap 占比是否变化；即使变化，页面缓存逻辑仍不是主要成本。

当前建议选 1，保留 G9 开放，不在 0.7.0 内做 fast path。

## 4. 复现

临时在 `public/index.php` 的 `require vendor/autoload.php` 后启用 profiler，并在 shutdown 时把 `Maho\Profiler::getTimers()` 追加到 `var/log/page-cache-profiler.jsonl`；请求 20 次后统计。分析完成后恢复 `public/index.php`，不提交。
