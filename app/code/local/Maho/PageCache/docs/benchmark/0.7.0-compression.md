# 0.7.0 HTML 压缩基准

> 状态：2026-11-25 完成
> 关联：[RFC-007 PERF-02](../rfc/RFC-007-performance-architecture.md)、[压缩配置规格](../specs/page-cache-07-compression.md)

## 方法

- PHP 8.5.13 CLI，`gzencode` / `gzdecode`，与 `Maho_PageCache_Model_HtmlCache` 使用同一函数。
- 每个样本先预热 2 次，再压缩 50 次；表中为 median / p95。
- level 1、3、6；默认仍是 6。
- 样本来自本地开发站：CMS 首页、分类页、商品页。`large.html` 是商品页重复 10 次；`dynamic.html` 是商品页插入 20 个 `PC_DYNAMIC_SERVER` 占位符和 fallback HTML。两者是合成样本，只用来看压缩率和耗时随页面增大的趋势。

## 结果

### 压缩后大小

| 样本 | 原始字节 | level 1 | level 3 | level 6 |
|---|---:|---:|---:|---:|
| CMS 首页 | 23,427 | 7,174 (30.6%) | 6,936 (29.6%) | 6,315 (27.0%) |
| 分类页 | 35,624 | 9,448 (26.5%) | 9,046 (25.4%) | 8,161 (22.9%) |
| 商品页 | 35,022 | 10,080 (28.8%) | 9,665 (27.6%) | 8,711 (24.9%) |
| 大型合成页 | 350,220 | 94,861 (27.1%) | 89,145 (25.4%) | 76,199 (21.8%) |
| 动态占位符页 | 41,142 | 10,309 (25.1%) | 9,875 (24.0%) | 8,865 (21.6%) |

### 压缩和解压耗时

| 样本 | L1 压缩 | L3 压缩 | L6 压缩 | L6 解压 |
|---|---:|---:|---:|---:|
| CMS 首页 | 0.156 ms | 0.202 ms | 0.494 ms | 0.085 ms |
| 分类页 | 0.261 ms | 0.256 ms | 0.469 ms | 0.077 ms |
| 商品页 | 0.203 ms | 0.248 ms | 0.448 ms | 0.088 ms |
| 大型合成页 | 2.407 ms | 3.163 ms | 6.091 ms | 0.861 ms |
| 动态占位符页 | 0.237 ms | 0.285 ms | 0.526 ms | 0.084 ms |

p95 与 median 接近；完整数据见 `raw/0.7.0-compression.json`。

## 结论

- level 6 比 level 3 少 7% 到 14% 的存储，比 level 1 少 10% 到 20%。对 Redis 或共享存储，节省的是每个页面的常驻内存。
- 35 KB 页面 level 6 压缩约 0.4 到 0.5 ms，比 level 3 多约 0.2 ms。这只发生在 MISS 写缓存时，和整页 PHP 渲染相比可以忽略。
- 35 KB 页面解压约 0.06 到 0.11 ms，350 KB 页面约 0.75 ms；命中路径的成本远小于重新渲染。
- 默认保留 level 6 和 4 KB 阈值。没有数据支持改成 level 1 或 3；level 9 未纳入本轮，预计只增加 CPU，收益很小。
- 压缩关闭、阈值调整和 level 调整现在都是配置项，方便在 CPU 受限或调试环境里回退。

## 复现

```bash
# 1. 在 local 模式准备页面并保存 HTML
curl -sS http://localhost:8000/ > var/tmp/cms-home.html
curl -sS http://localhost:8000/page-cache-test/ > var/tmp/category.html
curl -sS http://localhost:8000/page-cache-test-product/ > var/tmp/product.html

# 2. 运行基准
php docs/benchmark/compression.php --iterations=50 --warmup=2 \
  var/tmp/cms-home.html var/tmp/category.html var/tmp/product.html \
  > docs/benchmark/raw/0.7.0-compression.json
```

大型页和动态页的生成方式见本文方法一节；脚本只依赖 PHP CLI，不启动 Maho。

## 限制

- 这是单机 CLI 微基准，不含真实网络、缓存后端和并发。
- 样本只覆盖开发站的主题和页面；生产主题的 HTML 结构、重复度和文本比例会影响压缩率。
- 没有测 Brotli。Maho 的页面缓存只使用 gzip，避免引入新的扩展依赖。
