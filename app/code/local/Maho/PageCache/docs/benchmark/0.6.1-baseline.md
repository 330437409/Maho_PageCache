# 0.6.1 性能基线

- 日期：2026-11-24
- 模块版本：0.6.1 开发版
- 代码提交：`ac6032dc6`（审计 P1 修复），文档 HEAD `221faaba4`
- 目的：RFC-007 Phase 1 基线，用于比较 0.7.0 CacheEnvelope 和其他优化
- 结论：本基线只用于同环境相对比较，不代表生产容量
- 说明：这是 0.7.0 CacheEnvelope 实现前的 0.6.1 基线；当前开发版已使用 v2 envelope，复测需在 0.7.0 分支进行

## 2. 方法

每个场景：

- 300 请求/轮，并发 10，5 轮。
- 每轮开始前预热 1-2 次。
- 取 5 轮中位数。
- 每个请求记录状态码、`X-Maho-Cache`、延迟。
- 延迟为客户端端到端时间，包含 PHP built-in server 和网络栈开销。

脚本：

```bash
node docs/benchmark/run.mjs \
  --label b2-local-hit \
  --url http://localhost:8000/page-cache-test-product/ \
  --requests 300 --concurrency 10 --rounds 5 --warmup 2
```

原始数据在 `docs/benchmark/raw/`。

### 3.2 未测场景

## 4. 缓存读取次数

按当前代码路径静态分析：

| 场景 | Cache backend 读取 | 说明 |
|---|---:|---|
| B2 Local HIT | 5 | meta、getVersions 再读 meta、global、url、html |
| B1 Revalidating 304 | 版本和 meta 读取后返回 304 | 未插桩 |
| B0 No Cache | 0 页面缓存读取 | 完整渲染 |
| B5 Static | 0 | PHP 不参与 |

B2 的 5 次读取是 RFC-007 `CacheEnvelope` 目标的基线。0.7.0 目标为不超过 3 次。本次没有在 Symfony Cache 外层加 traceable wrapper，因此读取次数来自代码路径，不是运行时计数器。

## 5. 观察

1. **页面缓存收益明显**：B2 的 P95 从 231.9 ms 降到 64.5 ms，RPS 从 75.8 提到 237.9。收益主要来自避免完整 layout 和 DB 查询。
2. **Local HIT 仍受 PHP 启动和框架开销限制**：B2 的 P50 38.4 ms，而静态文件 P50 9.3 ms。即使命中，PHP 仍要启动、解析请求、计算 context 和输出。
3. **B1 与 B2 接近**：304 响应没有 body，但 PHP 仍参与；RPS 249.9，略高于 B2。
4. **代理和静态层远离 PHP 的启动成本**：B4 5126 RPS、B5 5758 RPS，而 B2 只有 238 RPS。CacheEnvelope 减少 2 次读取只占 B2 端到端时间的一小部分，因此不能由 B2 的微优化推导 15% P95。
5. **B3 Redis 比 B2 file 慢**：188.58 RPS / P95 65.4 ms，说明单节点 local 模式下 Redis 网络往返抵消了共享收益。Redis 的价值在多节点共享和统一淘汰，不在单节点极限吞吐。
6. **FPM 没有在这个微基准里超过 built-in server**：B2-FPM 155.75 RPS / P95 96.0 ms，B2 built-in 237.91 / 64.5 ms；B3-FPM 148.51 / 91.5 ms。这是第三方便携镜像 + nginx + bridge 网络的结果，不代表调优后的生产 FPM；但它说明“换 FPM”本身不是命中路径的性能答案。
7. **早期 B5 Python 数据**保留在 `0.6.1-b5-static.json`，其中一轮出现 600 RPS 异常；正式表使用 nginx 数据。
8. **FPM 环境不是完全等价**：`webdevops` 镜像的 PHP 构建、扩展集、nginx 配置和 bridge 网络与 built-in server 不同；B2/B3 的 FPM 数字应作为“便携环境”参考，不是最终容量规划。

## 6. 复现配置

```bash
# B0
./maho config:set -s default -i 0 page_cache/general/enabled 0
./maho cache:flush

# B2
./maho config:set -s default -i 0 page_cache/general/enabled 1
./maho config:set -s default -i 0 page_cache/general/mode local
./maho config:set -s default -i 0 page_cache/static/enabled 0
./maho config:set -s default -i 0 page_cache/stats/enabled 0
./maho cache:flush

# B1
./maho config:set -s default -i 0 page_cache/general/mode revalidating
./maho cache:flush
ETAG=$(curl -sS -D - -o /dev/null http://localhost:8000/page-cache-test-product/ | tr -d '\r' | awk 'tolower($1)=="etag:" {print $2; exit}')
node docs/benchmark/run.mjs --label b1 --url http://localhost:8000/page-cache-test-product/ \
  --requests 300 --concurrency 10 --rounds 5 --warmup 1 --header "If-None-Match: $ETAG"

# B4
./maho config:set -s default -i 0 page_cache/general/mode proxy
./maho config:set -s default -i 0 page_cache/static/enabled 0
./maho cache:flush
curl -sS -o /dev/null http://localhost:6081/page-cache-test-product/
curl -sS -o /dev/null http://localhost:6081/page-cache-test-product/
node docs/benchmark/run.mjs --label b4 --url http://localhost:6081/page-cache-test-product/ \
  --requests 300 --concurrency 10 --rounds 5 --warmup 2

# B5
./maho config:set -s default -i 0 page_cache/general/mode local
./maho config:set -s default -i 0 page_cache/static/enabled 1
./maho cache:flush
curl -sS -o /dev/null http://localhost:8000/page-cache-test-product/
docker run -d --name maho-nginx-static -p 8081:80 \
  -v "$PWD/var/page-cache/static/default:/usr/share/nginx/html:ro" nginx:alpine
node docs/benchmark/run.mjs --label b5 --url http://localhost:8081/page-cache-test-product/ \
  --requests 300 --concurrency 10 --rounds 5 --warmup 1
```

## 8. 对 RFC-007 的影响

- B2 的 5 次读取已确认，`CacheEnvelope` 的 ≤3 次目标有明确基线。
- P95 ≥15% 暂不作为本次基线结论；需要在 PHP-FPM + nginx + Redis 环境复测。
- B2/B3 已补 FPM 便携环境；0.7.0 正式 benchmark 仍应在目标生产 FPM/nginx 配置上复测。
- CacheEnvelope 开发中复测见 `docs/benchmark/0.7.0-cacheenvelope-dev-check.md`。
- 首页、分类、多 store、动态块页面尚未纳入本次基线，列入 0.7.0 完整 benchmark。
