# ADR-0007：动态块打孔分两期实现

## 状态

已接受。

## 背景

页面缓存最难的部分是动态块：购物车数量、登录状态、消息、form key、客户价格、最近浏览等。不同方案的成本不同：

- Ajax/ESI：Maho 只输出占位符，动态块由前端或代理补充，PHP 压力小。
- 服务器端占位符：Maho 缓存页面，命中时在 PHP 内重建动态 block，用户看到完整 HTML，但 PHP 压力大。
- 代理模型：为 product/category/CMS 生成懒加载代理，降低服务器端重建成本。

## 决策

- 第一期不做动态块打孔，只缓存可安全缓存的页面；有 session cookie 的请求全部 bypass。
- 第二期做 Ajax 和 ESI 注入，动态块使用白名单，默认不打孔。
- 第三期做服务器端占位符和 product/category/CMS 代理模型。
- 第一期不写空的占位符字段、不建占位配置、不实现未使用的接口。

## 理由

- 第一期先验证 HTTP 层、session skip、tag 失效和 purge，风险最低。
- Ajax/ESI 比服务器端重建简单，适合作为第二阶段。
- 代理模型和服务器端占位符复杂度最高，放到有了真实命中数据之后再做。
- 不做占位实现，避免后续为了兼容空字段而增加负担。

## 后果

- 第一期只能缓存没有动态块的页面；有 session cookie 的请求不缓存。
- 第二期需要新增前端 JS、ESI 配置和动态块白名单。
- 第三期需要重新评估 layout、block 和模型加载的性能。

## 备选方案

- **第一期就做服务器端占位符**：范围和风险最大，不采用。
- **只做 Ajax，不做 ESI**：实现简单，但无法利用代理拼接，第二期仍保留 ESI 作为可选。
- **永远不做服务器端打孔**：对没有 JS/代理的环境不友好，保留为第三期。
